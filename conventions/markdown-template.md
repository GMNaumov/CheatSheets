# Шаблон Markdown-материалов

Используйте эти образцы для новых файлов и при обновлении существующих заметок. Выбирайте структуру по назначению файла: навигация, справочник команд, руководство или справочная заметка. Удаляйте разделы, которые не нужны конкретному материалу.

## Общие правила

- Начинайте файл с одного заголовка `#` и одного-двух предложений о назначении материала.
- Разделяйте самостоятельные темы заголовками `##`, а отдельные операции или подпункты — заголовками `###`. Не пропускайте уровни заголовков.
- Пишите заголовки по смыслу задачи: «Показать все контейнеры», «Удалить том», «Проверить установку».
- Перед командой указывайте, зачем и при каких условиях её выполнять. Предупреждение о необратимых последствиях ставьте **до** команды.
- Используйте ограждённые блоки кода с языком (`bash`, `powershell`, `yaml`, `text`). Оставляйте в блоках только текст, предназначенный для копирования; заменяемые значения обозначайте понятными заполнителями.
- После команды поясняйте только неочевидные флаги, ожидаемый результат и важные ограничения. Не дублируйте очевидное описание.
- Давайте ссылки относительными путями. Для навигации используйте подписи, описывающие содержимое файла.
- Не разделяйте записи горизонтальными линиями: заголовки уже обозначают границы. Не добавляйте пустые разделы и необязательные метаданные.

## Навигационный README.md

```markdown
# Название раздела

Что находится в разделе и кому это пригодится.

## Команды

- [Краткий справочник команд](../docker/commands.md) — основные операции.

## Руководства

- [Установка в Ubuntu](../docker/guides/install-ubuntu.md) — последовательность действий и проверка результата.
```

Для короткого раздела достаточно описания и одного списка ссылок без дополнительных заголовков.
При копировании образца замените подписи и пути на файлы своего раздела.

## Справочник команд

````markdown
# Команды инструмента

Для каких задач предназначен справочник и в каком окружении работают команды.

## Группа задач

### Действие и объект

Кратко опишите назначение и условия выполнения.

```bash
tool command <значение>
```

**Результат:** что пользователь увидит или что изменится.

**Примечание:** неочевидные флаги, альтернативная форма или ограничение, если они нужны.
````

Для опасной операции разместите предупреждение непосредственно перед блоком команды. Если команда одна, можно обойтись без группы задач.

## Пошаговое руководство

````markdown
# Название результата

Что будет сделано и для какой системы предназначена инструкция.

## Перед началом

- Необходимое ПО, доступ и исходные данные.

## Шаг 1. Действие

Зачем нужен шаг и что следует проверить перед запуском.

```bash
tool command
```

## Шаг 2. Следующее действие

Описание следующего шага.

## Проверка результата

Как убедиться, что задача выполнена.
````

Объединяйте команды в одном блоке, только если они выполняются подряд в одном окружении. Необратимые действия выносите в отдельный шаг с явным предупреждением.

## Справочная заметка

```markdown
# Понятие или объект

Короткое определение и область применения.

## Основные сведения

Правило или объяснение с небольшим примером.

## Пример

Пример использования, схема или ссылка на рабочий файл.
```

Для короткой заметки достаточно заголовка, вводного абзаца и списка или примера без искусственных разделов.
